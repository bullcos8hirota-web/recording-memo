# 要件定義書 — 高精度録音・自動要約アプリ

## 1. 背景・目的
Plaud のような「会話を録音して自動で要約する」体験を、**Webブラウザ上・オンデバイス処理**で実現する。
音声データを外部サーバーに送信しないことで、会議・商談などの機密性の高い会話でも安心して使えるツールを目指す。

## 2. スコープ前提
- プラットフォーム: Webアプリ（PC ブラウザ、Chrome/Edge 優先）
- 処理方式: オンデバイス（文字起こし・要約とも端末内で完結、ネット送信なし）
- 主な利用シーン: 日本語の会議・商談の録音と議事録化
- 開発体制: 個人開発、まず MVP（最小構成で動くもの）を作る

この前提により、初期版では以下を **明示的にスコープ外** とする。
- スマホネイティブアプリ、デスクトップアプリ配布
- 多言語対応（英語等は Phase 後半で検討）
- サーバーサイド処理・アカウント基盤・課金
- リアルタイム配信共有、複数人での同時編集

## 3. ユーザー像・利用シーン
- 個人〜小規模チームで、社内会議・1on1・商談を録音し、後から議事録として見返したい人
- 録音データを社外に出したくない（機密情報を扱う）人
- 会議後にすぐ要点・決定事項・アクションアイテムを確認したい人

## 4. 機能要件

### 4.1 録音
- マイクからの音声録音（開始／一時停止／再開／停止）
- 録音中の経過時間・簡易波形表示
- 録音中でもタイトルやメモを仮入力できる
- 録音データはブラウザ内（IndexedDB）に保存し、リロードしても消えない

### 4.2 文字起こし（ASR）
- 録音終了後、または録音と並行して日本語の音声をテキスト化
- 処理はブラウザ内（WebGPU/WASM）で完結し、音声データを外部送信しない
- 進捗状況（モデル読み込み・処理中）をUIに表示
- 誤認識箇所を手動で修正できる（テキスト編集）
- タイムスタンプ付きセグメント単位でテキストを保持し、再生位置とハイライト同期する
- 話者分離（Aさん/Bさん等の区別）は **Phase 2 以降**（MVPでは単一テキスト起こしのみ）

### 4.3 自動要約
- 文字起こし結果から以下を自動生成
  - 会議概要（3〜5行程度のサマリー）
  - 主な論点・話題ごとの要点（箇条書き）
  - 決定事項
  - アクションアイテム（担当者が発言内で明示されていれば付記）
- 要約は端末内の軽量LLMで生成（オンデバイス）
- 要約結果は編集可能
- 要約の元になった文字起こし箇所へのジャンプ（対応関係表示）は Phase 2 以降

### 4.4 履歴・管理
- 録音一覧（タイトル・日時・長さ・要約冒頭のプレビュー）
- タイトル編集、タグ付け、検索（タイトル・文字起こし本文全文検索）
- 個別削除、複数選択削除
- Markdown / テキスト形式でのエクスポート（文字起こし全文＋要約）
- 音声ファイル（wav/webm）のダウンロード

### 4.5 再生
- 録音の再生（シーク、再生速度変更）
- 再生位置に対応する文字起こしセグメントをハイライト
- 文字起こしのクリックでその位置にシーク

## 5. 非機能要件

### 5.1 プライバシー・セキュリティ
- 録音音声・文字起こし・要約データは一切外部サーバーに送信しない（完全オンデバイス）
- 将来クラウドAPIを選択的に使う機能を追加する場合も、デフォルトはオフデバイス送信なしとし、利用者の明示的な同意（オプトイン）を必須とする
- ローカルストレージのデータはブラウザプロファイルに紐づく（他デバイス間の同期は対象外）

### 5.2 精度・品質
- 日本語の会議・商談音声を主対象とし、実使用に耐える文字起こし精度を目指す（体感で大きな誤認識が頻発しない水準）
- オンデバイスLLMによる要約は、クラウド最新LLMに比べ精度が劣る可能性がある点をユーザーに明示する（モデル選定はPhase 1で精度検証して決定）

### 5.3 パフォーマンス
- WebGPU 対応ブラウザでは文字起こしが録音時間に対して実用的な速度で完了すること（目安: 等倍〜数倍速）
- WebGPU 非対応環境では WASM フォールバックで動作するが、速度低下をUIで明示する
- 初回のみモデルダウンロードが発生する（数百MB〜）ため、進捗表示とキャッシュ（Cache API）による2回目以降の高速起動を必須とする

### 5.4 対応環境
- 推奨: 最新版 Chrome / Edge（WebGPU対応）
- 非対応ブラウザ・環境では機能制限または非対応メッセージを表示

### 5.5 可用性・データ保全
- ブラウザのストレージ容量上限に近づいた場合に警告を表示
- 誤操作による削除に対する確認ダイアログ

## 6. 制約・リスク
- オンデバイスASR/LLMは商用クラウドAPI（Whisper API, Claude等）に比べてモデルサイズ・精度上の制約がある
- ブラウザストレージはユーザーがキャッシュクリアすると消失し得る（バックアップ導線が必要）
- WebGPU非対応の古い環境・PCでは体験が大きく劣化する
- 長時間録音（1時間超）でのメモリ・処理時間は検証が必要

## 7. MVP完了の定義（Done基準）
1. ブラウザでマイク録音ができ、IndexedDBに保存・一覧表示できる
2. 録音した音声を日本語で文字起こしでき、結果を確認・編集できる
3. 文字起こしから要約（概要・要点・決定事項・アクションアイテム）が自動生成される
4. 履歴一覧から過去の録音を検索・再生・削除・エクスポートできる
5. 全処理がネットワーク送信なしで完結する（開発者ツールのNetworkタブで音声/テキストの外部送信が無いことを確認）
